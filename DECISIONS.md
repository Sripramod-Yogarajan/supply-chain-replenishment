# Decisions

Project-level decisions taken by the project owner on top of `build_manual.md` (which is kept
unchanged). The manual's rules, research objectives, datasets and provenance requirements are
not altered by anything below.

| Id | Date | Decision | Effect on manual |
| --- | --- | --- | --- |
| D-1 | 2026-11-04 | **Layout.** The repository root is the project root; there is no nested `fyp/` directory. The Python package is `src/supply_chain_rl/` (import name `supply_chain_rl`). | Naming only. Wherever the manual says `fyp`, read `supply_chain_rl`, e.g. `python -m supply_chain_rl.data.build`. |
| D-2 | 2026-11-04 | **Chosen settings vs derived facts.** Chosen settings (tag C) stay in `config.yaml`. Facts derived from the data are stored in a separate `derived.yaml` and are never written back into `config.yaml`. Phase 0 puts `data.n_days` there (needed to validate splits). Phase 1 verifies it against the raw files. | Replaces the manual's "write back to the config" mechanism for derived facts. Values and meaning unchanged. |
| D-3 | 2026-11-04 | **Applied in Phase 1, please confirm at G0:** `item_id` and `first_day` are results of the item-choice algorithm (manual 6.2), so they are written to `derived.yaml` (with the threshold actually used), and the `null` placeholders were removed from `config.yaml`. The evidence is in `data/processed/item_choice.md`. | Replaces the manual's write-back into the config; values and meaning unchanged. |
| D-4 | 2026-11-04 | **Tooling.** `venv` + `pip`, dependencies declared in `pyproject.toml`, fully pinned (with hashes) in `requirements.lock` generated by `pip-tools`. Ruff for lint and format, mypy (strict) for types, pytest for tests. No other tooling. Runtime dependencies are added when their phase starts: Phase 0 numpy and pyyaml; Phase 1 adds pandas, pyarrow, networkx, matplotlib, plotly. | Adds reproducibility and lint/type checks; no change to scope. |
| D-5 | 2026-11-04 | **Git.** Phase 0 is committed, including `build_manual.md` unchanged. Datasets, virtual environments, secrets and generated artifacts are never committed (`.gitignore`). | None. |
| D-6 | 2026-11-04 | **Seeding.** Named generator streams are derived from `(seed, name)` through `SeedSequence` with a hash of the name as spawn key, so adding or consuming one stream never changes another. | Implements the manual's determinism rule (0.1) and common random numbers (R10). |
| D-7 | 2026-11-04 | **Config hash.** `Config.hash()` gives a short stable hash of the settings plus `n_days`, to be stamped into logs and reports. | Reproducibility aid only. |
| D-8 | 2026-11-04 | **Store state check.** The "stores under one warehouse share a state" check uses the state prefix of the M5 store id (`CA_1` gives `CA`). Phase 1 re-asserts it against the real `state_id` column. | None. |
| D-9 | 2026-11-04 | **mypy scope.** `pandas-stubs` types label lookups as broad unions, which produced 70+ noise errors in table, plot and CLI code. Seven specific error codes are disabled only for `graph.*`, `data.build`, `data.dataco` and `tests.test_graph`; config, seeding and the core M5 logic stay fully strict. | Tooling only. |
| D-10 | 2026-11-04 | **Data over manual.** The owner allowed deviations from the manual where the data shows a better choice. First use: St2 maps to M5 store `CA_3` instead of `CA_2` (assumption A11), because CA_2 has a store-wide demand level shift. | Changes `config.yaml` network (`m5_store`), not the method. |
| D-11 | 2026-11-04 | **Lockfile deferred.** `requirements.lock` is not regenerated now (owner decision); it still lists only the Phase 0 packages and will be regenerated at the end of the project. `pyproject.toml` is the current source of truth for dependencies. | Supersedes the lockfile part of D-4 until then. |

Note on D-2: the approval text said `data.n_dayvalues`; this was read as `data.n_days` (the
number of days, 1941). Correct me if something else was meant.
